FIG 04 / MEMORY

Engineering details

Challenge

Build scripts that behave correctly in a container, preserve input integrity, and safely coordinate shared resources.

Approach

Inspect Linux process, CPU and cgroup interfaces; sort whole CSV records while verifying input hashes; run 102 reported requests across three hosts with a throttle limit of 10 and synchronized logs; collect periodic RSS and VSZ observations by process and user.

Tools

PowerShell 7, Debian Linux, containers, CSV, SHA256, ForEach-Object -Parallel, file locking, strace, ps and cgroup/procfs accounting.

Findings from original reports

Lab 2 recorded 300,000-row CSV sorting in 10.04 seconds (standard) and 7.19 seconds (parallel), an independently recalculated 1.40× reported speedup. Lab 3 recorded 102 requests across three services in 8.69 seconds serially versus 1.68 seconds concurrently (5.17× reported speedup). A 100-increment shared-counter experiment ended at 2 without synchronization and 100 with locking. Lab 4 documented periodic memory collection; the original memory-audit.ps1 source has now been recovered. All timings and race outcomes are historical report values, not newly rerun experiments.
