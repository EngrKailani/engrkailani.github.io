ENGINEERING EVIDENCE / AT A GLANCE

What was done, checked, and documented

Problem

Make multichannel thermal tests easier to monitor, document, and assess for stable temperature trends.

My contribution

Built and documented a Python-based acquisition, trending, and reporting workflow; later reconstructed the recovered application architecture and added an audit utility.

Engineering tools

Python, Tkinter, Pico TC-08, thermocouples, CSV/Excel; optional Arduino serial interface.

Validation method

Reviewed recovered source and used four passing synthetic tests for the CSV audit utility. A rolling 10-reading / 3.0 °C band describes software logic, not calibrated performance.

Documented result

Source supports an eight-channel interface, nominal one-second UI polling, trend plots, and reporting outputs.

Limitations

No new hardware calibration or timing validation; example traces are synthetic and original physical test outcomes are not publicly verified.

THERMAL VALIDATION / SOFTWARE VISUALIZATION

A clearer view of the testing workflow.

Instrument interface and live trending

The desktop application uses Tkinter for test configuration, channel selection and reporting. A separate graph window displays temperature trends with selectable channels. This illustration shows the type of interface, not a screenshot of the deployed application.

FIG 01 / APPLICATION

How the data moves through the system

A Pico TC-08 supplies thermocouple readings to the Python application through the vendor Windows driver. The application coordinates graph updates, test metadata and exports. An optional serial connection can send setpoints and feedback to Arduino control hardware.

FIG 02 / SYSTEM PATH
Data capture and reporting

Test metadata, selected temperature channels and sample numbers are exported to CSV, with an optional formatted Excel version.

Important timing limitation

Exported sample indices are not actual acquisition timestamps. Sampling jitter, driver accuracy and long-duration reliability require hardware testing.

How rolling stability is evaluated

The original display logic examines the range of the most recent valid readings. With the default settings, a 10-reading window is within the configured band when its maximum minus minimum is no greater than 3.0 °C.

Engineering details

Challenge

Manual monitoring and inconsistent reporting slow down thermal validation.

Approach

Combine Python data acquisition and live visualization with optional Arduino ambient-control integration, a rolling stability indicator, and structured exports.

Tools

Python, Arduino, Tkinter, temperature instrumentation, CSV and Excel.

Documented outcome

A more traceable and repeatable thermal-testing workflow through the surviving Python application. The original acquisition and UI source has been recovered, but no new instrument calibration or hardware performance tests have been completed in this archival pass.

Software architecture recovered from source inspection

The original code includes Pico TC-08 thermocouple acquisition, optional Arduino ambient control, a multi-channel trend display, and CSV and Excel reporting. I reconstructed the software architecture, documented the serial interface, and added a verification plan and standalone CSV audit utility. Four synthetic tests of the audit utility passed; physical thermal-testing results remain unverified.

Evidence & limitations

Evidence and publication boundary: The graphics describe recovered software structure and synthetic calculation examples, not actual thermocouple measurements. Internal engineering logs, employer records, proprietary reports and source files are not provided for download from this project page.
