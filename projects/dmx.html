PROJECT 15 / 16

This project brings a familiar browser interface to a hardware lighting-control problem. Choosing a scene or brightness setting produces commands for an Arduino-based DMX system.

EMBEDDED CONTROL / VISUAL CASE STUDY

From a browser scene to a lighting command

This project links a local browser interface to an Arduino Mega that prepares RGBW DMX frames. The visuals trace the implemented command path, explain DMX slot timing and show calculated scene and dimming behavior. They are source-informed graphics, not captured oscilloscope data or independently measured lamp performance.

Lighting demonstration

Existing portfolio footage gives the project a physical lighting reference before the diagrams explain the software and firmware. The recording is presented as a demonstration, not evidence of verified DMX electrical signaling.

FIG 01 / DEMO VIDEO

How the control chain works

Scene and brightness selections become local Flask HTTP requests. Flask sends newline-delimited serial text at 115,200 baud, the Arduino Mega parses commands, and its DMX transmitter writes RGBW channel values through a required external RS-485 interface.

FIG 02 / ARCHITECTURE

Inside a DMX frame

The firmware uses a zero start code followed by four RGBW slots and 508 unused channels. With 513 transmitted slots at 250 kbit/s in 8N2 format, the calculated minimum frame is 22.708 ms. Adding the programmed 25 ms loop delay gives a nominal upper estimate of about 21 cycles per second.

FIG 03 / TIMING MODEL

Scene sequencing and brightness scaling

The software defines fixed red, green, blue, white and off scenes, plus gradient and demo modes. Channel brightness uses integer arithmetic, so a 50% command maps an active base value of 255 to byte 127, not to a verified optical brightness percentage.

Engineering details

Challenge

Translate simple user controls into real output for RGBW lighting hardware.

Approach

Use Flask to receive browser inputs and send serial commands to Arduino for DMX output.

Tools

Python, Flask, Arduino, serial communication, DMX.

Recovered lighting-control system

The original Flask interface and Arduino Mega sketch are available in GitHub. The controller sends newline-delimited serial commands at 115,200 baud, and the firmware constructs DMX frames with a zero start code and four RGBW data channels. The original sketch's invalid fconst declaration was corrected; the Flask service now listens on localhost by default. The existing demonstration video is preserved, but physical DMX timing and fixture response have not been retested in this recovery.

Recovered engineering and verification

The source describes seven scene commands, dimming from 0% to 100%, a six-color gradient, and a 20-second nominal demonstration timeline. An independent offline reference model and 13 synthetic tests check the channel assignment, integer dimming, scene sequencing and timing calculations. Arduino compilation, physical signal integrity, luminaire channel mapping and current ratings require a subsequent hardware test. The original HTTP endpoints do not authenticate users, so the recovered app should remain local-only unless explicitly secured.

Evidence & limitations

Evidence boundary: Source inspection and offline synthetic tests establish the intended control logic only. Arduino compilation, RS-485 wiring, electrical DMX timing, output channel order, fixture response and lighting safety require hardware checks. No proprietary logs, raw measurements or source downloads are included on this page.
